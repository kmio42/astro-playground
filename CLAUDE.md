# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A personal sandbox for experimenting with astronomical calculations and visualizations. It computes and visualizes solar/lunar positions, rise/set times, moon phases, and coordinate transformations. All algorithms are based on Jean Meeus' *Astronomische Algorithmen* (Astronomical Algorithms).

## Running the Code

No build step required. HTML files run directly in a browser:

```bash
firefox mond.html
firefox erdposition.html
```

Exception: `sichtbarkeit.html` needs a local web server for the map, because the OpenStreetMap tile servers block requests without a Referer (as sent from `file://`): `python3 -m http.server 8000`, then open `http://localhost:8000/sichtbarkeit.html`. `erdemond3d.html` needs the same server, because WebGL may not use image files from `file://` as textures. The simple Python server sends no cache headers, so after changing a shared `.js` file the browser may keep the old one; reload with Ctrl+Shift+R. `sichtbarkeit.html` checks for the `visibility.js` functions it needs (`REQUIRED_VISIBILITY_API`) and shows a notice if they are missing.

The C++ files live in `cpp/` (`astro.cpp`, `astro.h`, examples in `cpp/beispiele/`, documented in `cpp/README.md`). They have no Makefile and are not integrated into any HTML page — they are a standalone reimplementation in the `astro::` namespace, kept compatible with C++11 (Arduino cores). Build an example: `cd cpp/beispiele && g++ -std=c++11 -I.. sonne.cpp ../astro.cpp -o sonne`.

## Architecture

**`astro.js`** is the core mathematical library (~1385 lines), a port of `cpp/astro.cpp` with the same function names, parameters and result objects (see `cpp/README.md`). Self-contained, wrapped in an IIFE; in the browser all public names are global, in Node.js they come from `require('./astro.js')`. Angles are numbers in radians, time is a Julian Day number in UT (ΔT is applied internally), locations are `{ longitude, latitude, elevation }` objects (radians, east positive). It exports:

- **Constants**: `DEG2RAD`, `RAD2DEG`, `AU_KM`, `EARTH_RADIUS`, `MOON_RADIUS`, `MOON_ORBIT_RADIUS`, `EARTH_SEMI_MAJOR_AXIS`, `OBLIQUITY_J2000`, `EquinoxType`, `ApsisType`
- **Time**: `julianDayFromCalendar()` (optional calendar `'auto'|'julian'|'gregorian'`, floor so it also works before −4712), `calendarFromJulianDay()` (inverse, Julian/Gregorian), `julianDayFromDate()`, `julianDayToDate()`, `julianDayMidnight()`, `deltaT()`, `taiMinusUtc()`, `dynamicalTime()`, `julianDayFromDynamicalTime()`, `calculateEaster()`
- **Solar**: `calculateSunPosition()`, `calculateObliquity()` (Laskar, formula 21.3, valid about ±10 000 years), `calculateEquationOfTime()`, `calculateEquationOfTimeParts()` (Smart's formula 27.3 split into eccentricity, obliquity and mixed term), `calculateEarthTrueAnomaly()`, `calculateEarthEccentricity()`, `calculateGreenwichSiderealTime()`, `calculateLocalSiderealTime()`, `calculateSunRiseSet()`, `calculateEquinoxSolstice()`, `calculateNextEarthApsis()`
- **Coordinate transforms**: `calculateEquatorial()`, `calculateHorizontal()`, `calculateTopocentric()`, `calculateParallacticAngle()`, `calculateRefraction()` (formula 15.4, true → apparent altitude)
- **Lunar**: `calculateMoonPosition()`, `calculateMoonPositionSimple()`, `calculateMoonIlluminatedFraction()`, `calculateMoonOrientation()` (libration, position angle), `calculateMoonAscendingNode()`, `calculateMoonRiseSet()`, `calculateNextMoonApsis()`, `calculateNextMoonNode()`
- **Utilities**: `interpolate()`, `normalizeAngle()`, `normalizeAngleSigned()`, `angleFromDms()`

When changing an algorithm, change `astro.js` and `cpp/astro.cpp` together; their results agree to about 1e-11.

**`render.js`** — small shared 3D rendering helpers: rotation matrices (`createRotationMatrix(axle, angle)`, `multiplyMatrix()`, `transposeMatrix()`, `applyMatrix()`) and canvas line drawing for spheres (`drawPolygonLine()`, `calculateLatitudePoints()`, `calculateLongitudePoints()`). Used by `erdposition.html` (tilted Earth view), `mond.html` and `moonRender.js`.

**`moonRender.js`** — moon surface rendering shared by `mond.html` and the Node.js script `renderMoon.js` (renders moon phase PNGs, needs `npm install canvas`): `drawMoonPhaseTexture()` (pixel-by-pixel mapping of the NASA LROC texture) and `drawMoonPhasePicture()` (moon photo `mond2.png` with pixel-by-pixel shadow). Both take phase, position angle of the axis, libration and parallactic angle into account. Depends on globals from `astro.js` and `render.js`.

**`ui.js`** — shared UI state and formatting helpers (`radToDegString`, time formatting, common variables like `datetime`, `latitude`, `longitude` in degrees, `useLocalTime`). `getLocation()` turns the inputs into the location object for `astro.js`, `siderealTimeHours(jd)` gives Greenwich sidereal time in hours, `normalizeDegrees()` normalizes display values in degrees. `zoneOffsetHours(date, zone)`, `zonedDate(y, m, d, h, min, zone)` (years 0–99 and negative years taken literally) and `zonedParts(date, zone)` convert between instants and wall time in an IANA time zone (`zone` null = the browser's). „Lokalzeit“ means the zone in `localZone` (null = browser; tours set `'Europe/Berlin'`). `dayUtcOffset()` and `timeZoneLabel()` give the time zone for day-based values (rise/set) depending on the "Lokalzeit" checkbox; `calculateSunRiseSet()`/`calculateMoonRiseSet()` take it as optional third argument `utcOffset`. Loaded after `astro.js` by the pages that opt into the shared modules. If the page also loads `embed.js`, `initUI()` takes the location from `kmEmbed.usePlace()` (fallback 50° N, 10° O instead of the stored-only `loadData()`) and the start time from `kmEmbed.state.t`. The generated forms are card-style panels (`ui-panel`: location fields with GPS/„Ort merken“ and a latitude slider `#latitudeSlider` (left out with `data-slider="none"` on `#locationControls`, as in `sichtbarkeit.html`), time grid with a UTC | Lokalzeit segmented switch that is still the checkbox `#localTime` inside a `<label>`, a „Jetzt“ button `setTimeNow()`, layout via container query on the panel width) and time-step groups „− label +“ (`ui-time-buttons`, `ui-step`); element IDs are unchanged because pages (e.g. `sichtbarkeit.html`) move or read them. `injectUiStyles()` prepends the stylesheet to `<head>` with colors from the page tokens (`--surface`, `--surface-2`, `--text-2`, `--border`, `--accent`, light fallbacks), so page rules override it at equal specificity. Time buttons use pointer events (mouse, touch, pen): click steps once, holding repeats every 200 ms, `pointerup`/`pointercancel`/`pointerleave`/window `blur` stop it. Coordinates accept a decimal comma.

**`embed.js`** — start state from the URL and embed mode for the model pages. Loaded in `<head>` before the page script; provides `kmEmbed`: `state` (`t` as Date, `lat`, `lon`, `fixedPlace` (`ortfest`), `view`, `step` (tour step from 1), `tour`, `tourName` (value of `tour` on pages with several tours), `layers` (list), `play` (`day`/`month`/`year`), `controls` (`full`/`min`/`none`); null if missing or invalid — also without embed mode, so a link can open the page in a given state), `active` (URL parameter `embed`), `id`, `ready()`, `usePlace(fallback, apply)` (reader's location: calls `apply(lat, lon)` now and whenever it changes — another frame or tab stored/forgot a location (`storage` event), input in the location line; precedence `ortfest` → stored `localStorage` `latitude`/`longitude` (decimal or DMS) → `lat`/`lon` → fallback; in embed mode it fills `#kmPlace` with a line „📍 Breite [slider] Ort: … · ändern“ (slider first so it does not move while the text changes; 0.5° steps, also overrides `ortfest`, like own input) and „ändern“ that opens lat/lon inputs, „Mein Standort“ (GPS, unrounded), „Ort merken“, „Ort vergessen“), `visible`/`onVisibility(fn)` (false while the frame is off-screen (IntersectionObserver) or the tab hidden; pages stop their animation loop), `fullscreen`. In embed mode it hides blocks marked `data-embed="hide"` (heading, intro, explanations, location form), with `controls=min` also `data-control="extra"`, with `none` all `data-control` elements; sets `data-theme` (`theme=light` default, `dark`, `auto`), reports the body height to the parent page via `postMessage(…, '/')` (same origin only; `{ source: 'km-model', type: 'height' | 'ready', id }`), lets the mouse wheel reach canvases only after a click into the frame or with Ctrl (otherwise the parent scrolls, a hint appears), and keeps `touch-action: pan-y` on canvases until a canvas is tapped (4 s after the last touch it reverts). The parent's message `{ source: 'km-host', type: 'fullscreen', on }` switches to fullscreen behaviour (own scrolling, wheel and touch free). On all model pages the location is the first control (embedded: `#kmPlace`). Embeddable pages: `tagbogen3d.html`, `himmelsachse3d.html`, `erdposition.html`, `mond.html` (both via `ui.js`: `t`, location; time panel and buttons `data-control="basic"`, Mond options `extra`), `tageslaenge.html` (`t` selects year and day of the key figures; `layers` picks the sections `gain`, `times`, `eot`, `table` (default all; also after a tour and for tour steps without `show`); `tour` shows start buttons for its tours, `tour=<name>` only that one, `step` starts it), `mondbahn.html` (`t`, `view=earth|geo`, `play`, `tour=schleifen` with `step`), `erdbahn3d.html` (`view=oblique|top|edge|earth`, `layers` incl. `exaggerate`, `play=year|day`), `erdemond3d.html` (`tour=height|nodes|apsides` shows only that start button, with `step` it starts at once; `step` without `tour` in embed mode only sets the step's state; `view` from `VIEWS`, `layers` = `data-layer` names, `play` day/month/year = 1 h/s, 1 day/s, 1 month/s; the frame loop stops while invisible; embedded, the viewport height comes from the width (4:3) instead of `vh`). Tours follow one pattern on all pages: standalone the start button(s) are visible, embedded only with `tour` (with a name only that tour's button); `tour` plus `step` starts the tour at that step, `step` alone (embedded) only applies the step's state without the text box; a tour with text box computes for `TOUR_PLACE` (50° N, 10° O) and German time (MEZ/MESZ: `displayZone` in the canvas models, `localZone` with „Lokalzeit“ forced on in `erdemond3d.html`, mode `de`/`cet` in `tageslaenge.html`), disables the location inputs, hides `#kmPlace` (`body.touring`) and restores the reader's location afterwards (a location stored meanwhile is kept for afterwards; pages using `ui.js` set `window.kmPlaceHold`). A page applies `kmEmbed.state` itself (`applyEmbedState()` in `tagbogen3d.html` and `himmelsachse3d.html`: step via `startTour(index, showBox)`, then `t`, `view`, `layers` (`fixedLayers` in `visible()`), `play`).

**`modelle.js`** — loader for a page that embeds models (e.g. a blog post): replaces each placeholder `<div class="km-modell" data-modell="tagbogen" id="…" data-datum="2026-06-21 10:00" data-ort="50,10" data-ort-fest="ja" data-ansicht="east" data-schritt="4" data-tour="ja|<name>" data-ebenen="…" data-abspielen="tag|monat|jahr" data-poster="ja|nein" data-bedienung="voll|min|keine" data-farben="hell|dunkel|auto" data-hoehe="3/4">` (its content is the no-script fallback) with an `iframe` of the model page (same folder as `modelle.js`, `?embed&…&v=VERSION`, aspect ratio until the first height message) plus a line „Vollbild · Eigene Seite ↗“ (fullscreen of the iframe where the browser supports it; the link opens the page with the same state). With a poster (default for models with `poster`, i.e. `erdemond`) it first shows a preview image (`posters/*.jpg`, rendered from the page in headless Chromium with software WebGL, or an `<img>` inside the placeholder) with a button „▶ Modell laden (size)“ and creates the iframe only on click; on screens ≤ 700 px or with Save-Data it adds the model's small-texture parameter (`klein`). Models are listed in `MODELS` (`tagbogen`, `himmelsachse`, `erdposition`, `mond`, `tageslaenge`, `erdbahn`, `mondbahn`, `erdemond`; add a page only once it supports `embed.js`). `const VERSION = 'dev'` is replaced when publishing. Accepts height messages only from its own iframes and the same origin. Runs once even if included several times (`window.kmModelle.scan()`).

**`canvas3d.js`** — helpers for schematic 3D models in Canvas 2D (global `canvas3d`): vectors `V` (incl. `rotX`, `rotZ`), `Scene` (camera {az, el, dist} around a target with near-parallel projection, `begin()`, `project()`, `pixelScale()`, `facing()`, `stroke()`/`strokeWhere()`/`fill()`/`label()`/`dot()`, `sphere()` = disc with day and night side for a sun direction, `animateTo()`/`step()`/`finish()` camera tweens, `enableInteraction()` drag/wheel/pinch) and `Tour` (start button `#tourStart`, box `#tour` …; `fixPlace(on)` hook for fixed place and German time, `fromEmbedState()` with the common embed rules). Used by `erdbahn3d.html`; `tagbogen3d.html` and `himmelsachse3d.html` still have their own copies of these parts.

**`longterm.js`** — Earth orbit and axis over millennia for the time-lapse in `erdbahn3d.html` (DOM-free like `astro.js`, browser globals / Node `require`): mean orbital elements of the Earth (Meeus table 31.A, `earthElements()`), general precession in longitude (`generalPrecession()`), position from Kepler's equation (`earthHelio()`), equinoxes/solstices, perihelion/aphelion and the lengths of the half-years for any year (`seasonsOfYear()`, `apsisOfYear()`, `halfYears()`; up to a quarter of an hour resp. two days off, no perturbations), the celestial north pole of date in J2000 ecliptic coordinates (`poleOfDate()`) and stars near its path (`POLE_STARS`, `starVector()`, `poleStars()`). Range `LONGTERM_YEARS` −8000 … +12 000 (validity of the formulas).

**`coastlines.js`** — `COASTLINES`: Natural Earth 1:110m coastlines (public domain, „Made with Natural Earth“), simplified to 0.1°/0.4° steps, as flat [lon, lat, …] arrays per line.

**`visibility.js`** — visibility of sun and moon from a viewpoint (concept in `Konzept-Sichtbarkeit.md`). DOM-free IIFE like `astro.js` (browser: globals, Node: `require`). Unlike `astro.js` it works in **degrees**, azimuth from **north**, apparent altitude (with refraction). A viewpoint `{ name, sectors, horizon, observations }` is a mask: visible = inside a sector rectangle (or no sectors) and above the horizon line. Provides `sunDirection()`, `moonDirection()` (topocentric, hourly ephemeris + interpolation), `visibilityLevel()`, `findVisibilityIntervals()`, `computeLevelGrid()`/`computeLevelSeries()`, `findFullMoons()`, `findMoonPhases()` (new/first quarter/full/last quarter), `observationDirection()`. Stage 2 (environment): `horizonFromBuildings()` (OSM outlines, ray per 0.25° azimuth), `terrainTileList()`/`decodeTerrarium()`/`createTerrainSampler()` (Terrarium tiles of any size: Mapterhorn 512 px bare-earth DTM, AWS Terrain Tiles 256 px as fallback), `terrainProfile()` (upper convex hull per azimuth, so eye height stays adjustable) and `horizonFromTerrain()`; `compileViewpoint(vp, profile)` takes the maximum of the hand-drawn horizon and this computed profile. Stage 3 (room/balcony): `viewpoint.scene` describes a room (walls with window openings and reveals) and/or a balcony (slab above, parapet, dividers); `compileScene()` turns it into axis-aligned opaque rectangles in room coordinates (x along the facade, y outward, z up) plus a 0.25° raster mask, `sceneVisible()` uses the raster with an exact ray test at transitions, `sceneObstacle()` names the blocking part, `sunPatch()` samples the sunlit floor, `sunPatchTable()`/`sunPatchArea()` precompute the patch area per sun direction (2° grid) for year overviews. Tests: `node testVisibility.js` (also compares `calculateRefraction` with `cpp/astro.cpp` if g++ is available).

**`orbit3d.js`** — geometry for the 3D model `erdemond3d.html` (concept in `Konzept-ErdeMond3D.md`). DOM-free IIFE like `astro.js` (browser: globals, Node: `require`). Geocentric frame: ecliptic and mean equinox of date, x to the vernal equinox, z to the ecliptic north pole, unit Earth radius; rotation matrices are 9-element row-major arrays (body axes → ecliptic, body x to longitude 0°, z to north pole). `sceneState(jd)` (sun direction, moon position, illuminated fraction, libration, Earth/Moon rotation), `earthRotation()` (GMST, obliquity), `moonRotation()` (built from libration l, b and position angle P of `calculateMoonOrientation`, so (l, b) faces Earth), `moonPath()`, `meanMoonOrbit()`/`ellipsePoints()` (mean elements, perigee longitude L′ − M′), `moonNodePassages()`, `moonApsides()`, `nearestEvent()`, `nextMoonPhase()` (secant search on λ_moon − λ_sun), `subPoint()`. Eclipses: `sunVisibleFraction()` (overlap of two discs, same formula as the shadow shader), `eclipseGeometry()`/`eclipseAt()` (moon distance from the Earth's shadow axis with Chauvenet's 1.02 enlargement, umbral/penumbral magnitude; gamma of the Moon's shadow axis, total/annular/partial), `greatestEclipse()` (golden-section search near a syzygy), `findEclipse(jd, 'lunar'|'solar', backward)`.

**`gl3d.js`** — small own WebGL2 helper (no external library), all names under the global object `gl3d` (Node: `require`, only the math part). mat4 column-major, `OrbitCamera` (z up, camera-relative rendering: view matrix with the eye at the origin, object positions shifted by the eye in double; mouse/touch, `animateTo`, `ray`, hooks `onChange`/`onPan`/`onRotate`), `sphereGeometry()` (UVs for equirectangular maps, 0° longitude at the image center, north at v = 0), `discGeometry()`, `lineGeometry()`/`createLineMesh()` (segments as screen-space bands with width in pixels and dashes; fixed attribute locations `ATTR`), `createProgram()` (`program.set(name, value)` picks the uniform type), `createMesh()`, `loadTexture()` (sRGB option), `projectPoint()`, `raySphere()`. Tests for `orbit3d.js` and `gl3d.js`: `node testOrbit3d.js`.

**`prepareTextures3d.py`** — builds `textures/` (Earth day 4k from Blue Marble NG May 2004, night 2k from Black Marble 2016, water mask 2k from GEBCO land heights plus blue-ness of Blue Marble, moon normal map 2k as JPG from LOLA `ldem_16_uint.tif`, channels east/north/up; small variants `earth_day_2k.jpg` and `moon_normal_1k.jpg` for the data-saving version `erdemond3d.html?klein`, 1.7 instead of 3.6 MB) from the NASA downloads in `textures/src/` (git-ignored, URLs in the script); single steps by name, e.g. `python3 prepareTextures3d.py moon_normal`. The moon color uses `lroc_color_2k.jpg` from the project root.

**`cpp/astro.cpp` / `cpp/astro.h`** — C++ reimplementation of the same algorithms in the `astro::` namespace. Standalone, no build integration. `JulianDay` holds UT and applies ΔT (leap-second table) itself; `ASTRO_EXACT_DELTA_T=0` switches to a fixed 69.184 s. Also in `cpp/`: `moon_testbench.cpp` (accuracy vs. NASA, results in `Testbench-Mond.md`), `Plan-Mondaufgang.md`.

**`easter.py`** — Python script computing Easter dates (Meeus/Jones/Butcher algorithm) with a matplotlib visualization.

**`astro-template`** — bare HTML/CSS scaffold used as a starting point for new pages.

## Key Conventions

- Identifiers (variables, function names) are in English; comments are in German
- Angles in `astro.js` are radians (`DEG2RAD`/`RAD2DEG` to convert); degrees only in UI inputs and display

- Location inputs are latitude/longitude in decimal degrees (`ui.js` globals); `getLocation()` converts them for `astro.js`
